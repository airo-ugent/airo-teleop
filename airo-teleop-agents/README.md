# IDlab-AIRO teleop agents package

This package provides common bindings between teleop devices (airo-teleop-devices) and manipulators (airo-robots). These are intended to be plug-and-play, e.g. for a teleoperation demo. For example: if you want to control any UR arm and parallel position gripper with a Gello teleoperation arm, you'd instantiate the Gello4UR_ParallelGripper class from `gello_teleop_agents.py`. See also the `examples` folder.

Executing the action that a TeleopAgent returns is done outside of the scope of the TeleopAgent class. This is because the user must be free to use different movement commands (e.g. high frequency servoing vs discrete, low frequency moves), to change the order of the UR and gripper move command, to decide whether to .wait() for a gripper and/or UR command, ... .

The SpaceMouse agents take an `action_mode`: `"absolute"` (default) returns the new TCP pose (and gripper width), `"delta"` returns the step itself as `[dx, dy, dz, drx, dry, drz(, dgripper)]` and needs no robot connection, e.g. for recording delta-action datasets.

Phone teleoperation (iOS/Android) is available via `Phone4PositionManipulator`. See `examples/phone4ur_example.py`. Requires `lerobot[phone]`.

Meta Quest VR teleoperation is available via `Vr4PositionManipulator` and `Vr4PositionManipulator_ParallelGripper` (`vr_teleop_agents.py`), on top of `VrTeleopDevice` (setup in the airo-teleop-devices README). One controller drives one arm with a clutch: hold GRIP to move (the TCP follows the controller's motion since the press, in the robot base frame), release it to reposition your hand; holding the TRIGGER as well scales the motion down by `precision_scale` (default 0.25) for precise positioning, without a jump when pressed or released mid-stroke; the gripper keeps the width it has at start and steps open while B is held, closed while A is held (X/Y on the left controller; `gripper_mode="analog"`/`"binary"` use the trigger instead). Recenter the headset while facing the robot base axis given as `operator_forward_axis`. The robot never moves without a fresh, valid pose and a held grip, and steps are clamped (`max_translation_step_m`, `max_rotation_step_rad`). See `examples/vr4ur_schunk_example.py` (prints only until `CONTROL_ROBOT = True`).
